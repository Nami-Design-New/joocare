# حصر البيانات الثابتة وغير المرتبطة بـ API في حساب المرشح

تاريخ المراجعة: 17 نوفمبر 2026.

## نطاق المراجعة

هذا الملف يخص **المرشح / Candidate / User فقط**: صفحات `/[locale]/candidate/*`، وتفاعل المرشح مع عرض الوظائف والتقديم عليها في `/[locale]/jobs/*`، والمحادثات التي يصل إليها من الهيدر.

الحصر مبني على تتبّع المسارات والمكوّنات والـ hooks ومصادر البيانات في الكود، وليس على اختبار استجابات السيرفر. عبارة «غير مربوط» هنا تعني أن التنفيذ الحالي يستخدم بيانات تجريبية أو حالة محلية بدل طلب API للعملية المذكورة؛ ولا تعني بالضرورة أن الـ backend لا يوفّر endpoint لها.

لا يشمل الحصر لوحة الشركة أو إدارة المرشحين من حساب الشركة. ولا تُعدّ الترجمات، الأيقونات، الصور الافتراضية، إعدادات الواجهة، والاختيارات المحدودة مثل نعم/لا بيانات API ناقصة بحد ذاتها.

## 1. المعلومات الإضافية للمرشح

**المسار:** `/candidate/profile/additional-info`.

### ما الذي لا يزال محليًا؟

- النموذج يبدأ من `ADDITIONAL_INFO_PREVIEW` بدل تحميل بيانات المرشح لهذا النموذج. من أمثلته: العربية والإنجليزية، إمكانية الانتقال ورخصة القيادة بقيمة `yes`، قطاعات `Hospitals` و`Home Healthcare`، وحالة `open-to-work`، وامتيازات سريرية تجريبية.
- زر الحفظ ينفّذ `setSaved(values)` ثم `form.reset(values)` ويعرض رسالة نجاح، بدون طلب API. التعديلات لا تُحفظ على السيرفر وتُفقد عند إعادة تحميل الصفحة.
- هذا ينطبق على الأقسام السبعة: المؤهلات والتراخيص، اللغات، الانتقال ورخصة القيادة، التفضيلات المهنية، الامتيازات السريرية، البيانات الشخصية، والراتب الحالي والمتوقع.
- قائمة اللغات `LANGUAGE_OPTIONS` وقائمة القطاعات `INDUSTRY_OPTIONS` مكتوبتان محليًا في ملف البيانات التجريبية.
- بطاقة اكتمال البيانات تُحسب من القيم المحفوظة محليًا عبر `getProfileCompletion(saved)`، ولا تُحمّل كنسبة محفوظة للمرشح. الحساب المحلي نفسه يمكن أن يبقى إذا كان مقصودًا؛ الربط الناقص هو مصدر القيم وحفظها.

**الربط الموجود بالفعل:** عدد من قوائم الاختيار يستخدم API، منها الدول والمدن والخبرات والمستويات الوظيفية والتعليم والتراخيص والشهادات والمسميات الوظيفية وفترة الإشعار والعملات. تحميل قائمة الخيارات لا يعني أن بيانات النموذج نفسها تُحمّل أو تُحفظ.

**المطلوب للربط:** تحميل قيم المرشح الفعلية وحفظ التعديلات، واستبدال قوائم اللغات والقطاعات التجريبية بمصدر البيانات المعتمد، ثم احتساب الاكتمال من القيم الفعلية.

## 2. مطابقة الوظائف بالذكاء الاصطناعي — AI Job Match

**المسار:** `/candidate/ai-job-match`.

- الوظائف المعروضة مصدرها `JOB_MATCH_PREVIEW`: أربع وظائف تجريبية بنسب `92` و`78` و`62` و`47`، وبأسماء شركات ورواتب ومواقع ومميزات ثابتة.
- العدد الإجمالي `JOB_MATCH_PREVIEW_TOTAL = 57` ثابت، وليس إجمالي نتائج API.
- حفظ التفضيلات وتعديلها يحدّث `useState` فقط ويعرض رسالة نجاح. لا يوجد تحميل لتفضيلات محفوظة أو إرسال لحفظها على السيرفر.
- قائمة الشركات المفضلة `PREFERRED_COMPANY_OPTIONS` ثابتة، مثل Pfizer وMerck وCleveland Clinic.
- تغيير الصفحة يحدّث رقم الصفحة فقط؛ لا يوجد طلب نتائج جديدة أو تقسيم لمصفوفة النتائج حسب الصفحة.
- خيار النتائج ذات المطابقة العالية يفلتر البيانات التجريبية محليًا. باقي التفضيلات لا تُستخدم للحصول على نتائج فعلية مطابقة لها.
- روابط العرض والتقديم تتكوّن من المعرّفات التجريبية، مثل `/jobs/match-1`، وليست معرّفات وظائف محمّلة لهذه النتائج من API.
- صفحة المسار تختار `empty` في فرعي شرط `scenario`، فتبدأ شاشة فارغة حتى يضيف المستخدم تفضيلات محليًا؛ ظهور هذه الشاشة لا يعكس استجابة API.

**الربط الموجود بالفعل:** قوائم المجالات، تصنيفات الوظائف، المسميات الوظيفية، الدول، والمستويات الوظيفية تستخدم lookup hooks متصلة بالـ API.

**المطلوب للربط:** تحميل وحفظ التفضيلات، تحميل الشركات، وطلب نتائج المطابقة مع نسب حقيقية وإجمالي وتقسيم صفحات ومعرّفات وظائف صحيحة.

## 3. من شاهد ملفك الشخصي — Profile Insights

**المسار:** `/candidate/profile-insights`.

- قائمة `PROFILE_VIEWERS_PREVIEW` تُنشئ 11 زيارة تجريبية من سبع شركات مكتوبة في الكود.
- أسماء الشركات وأنواعها وشعاراتها ومعرّفاتها ثابتة؛ وجود رابط لشركة حقيقية لا يجعل الزيارة نفسها حقيقية.

## 4. إنشاء السيرة الذاتية — CV Builder

**المساران:** `/candidate/build-cv` و`/candidate/build-cv/create`.

| الجزء                  | التنفيذ الحالي                                                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| وجود سيرة أو مسودة     | تحدّده معاملات `?state=exists` أو `?state=draft`؛ البداية الافتراضية `intro`، بدون قراءة حالة السيرة من API                                                 |
| آخر حفظ وتقدّم المسودة | `CV_BUILDER_PREVIEW_SUMMARY` يحتوي تاريخًا ثابتًا `18 Sep 2026` وخمس خطوات مكتملة من عشر                                                                    |
| عرض السيرة وتعديلها    | وضع `edit` وعرض السيرة من صفحة البداية يستخدمان `CV_BUILDER_PREVIEW_VALUES` باسم `Ahmed M. Ali` وبيانات اتصال وتعليم وخبرات وشهادات وأبحاث ومؤتمرات تجريبية |
| استكمال المسودة        | `getDraftCvValues()` ينسخ أول خمسة أقسام من السيرة التجريبية بدل قراءة مسودة المستخدم                                                                       |
| إنشاء سيرة جديدة       | يبدأ بقيم فارغة، وتبقى المدخلات داخل نموذج الصفحة؛ لا تُرسل لإنشاء سجل على السيرفر                                                                          |
| الحفظ والمتابعة لاحقًا | يفتح رسالة نجاح ثم ينتقل إلى `?state=draft`، بدون حفظ محتوى النموذج                                                                                         |
| حذف المسودة            | يغيّر الحالة المحلية أو ينتقل لصفحة البداية، بدون حذف سجل على السيرفر                                                                                       |
| المعاينة               | تُبنى في الواجهة من قيم النموذج الحالية؛ وفي صفحة البداية من القيم التجريبية                                                                                |
| تحميل PDF              | يحمّل دائمًا `/assets/company-projects/sample-cv.pdf` مع تغيير اسم الملف؛ لا يولّد PDF من محتوى السيرة المعروض                                              |
| صورة السيرة            | تُحفظ كرابط `blob:` محلي باستخدام `URL.createObjectURL`، بدون رفعها إلى السيرفر                                                                             |
| زر Apply داخل المعاينة | ينتقل افتراضيًا إلى `/candidate/build-cv`؛ لا يرسل السيرة أو طلب تقديم                                                                                      |

**قوائم وبيانات ثابتة داخل الخطوات:**

- الجنسيات، الدول، مواقع المؤتمرات، اللغات، المسميات الوظيفية، فئات سنوات الخبرة، وأنواع التوظيف مصدرها `cv-builder-options.ts`، وليست lookup requests في هذه الأداة.
- المهارات المقترحة `RECOMMENDED_SKILLS` قائمة ثابتة في الملف نفسه.
- اقتراحات الملخص المهني `SUGGESTED_SUMMARIES` ثلاثة نصوص ثابتة؛ زر التحديث يتنقل بينها محليًا، بدون توليد أو طلب API.
- نص حديث التخرج `FRESH_GRADUATE_PROFILE` قالب ثابت.
- حالات مثل الحالة الاجتماعية ومستويات اللغة وسنوات النشر موجودة محليًا أيضًا؛ هي اختيارات يمكن أن تبقى محلية حسب عقد البيانات، بخلاف بيانات المرشح والاقتراحات التجريبية.

**المطلوب للربط:** قراءة حالة السيرة ومحتواها ومسودتها، إنشاء وتحديث وحذف وحفظ مسودة فعلية، رفع الصورة، استخدام مصادر القوائم والاقتراحات المعتمدة، وتوفير PDF يعكس محتوى السيرة. المعاينة المحلية يمكن أن تبقى جزءًا من الواجهة.

## 5. تحليل السيرة بنظام ATS

**المسار:** `/candidate/cv-match-ats`.

- زر التحليل يغيّر حالة الواجهة إلى `analyzing` ثم يعرض `results` بعد مؤقّت `2500ms`، بدون إرسال ملف السيرة للتحليل.
- `ATS_PREVIEW_RESULT` يحتوي درجة ثابتة `85` وخمس ملاحظات تحسين ثابتة لا تتغيّر حسب محتوى السيرة.
- اسم الملف الاحتياطي `saeedCv.pdf` تجريبي.
- أوضاع `intro` و`analyzing` و`results` و`coming-soon` يمكن اختيارها بمعامل `?state=`. الإعداد الحالي `CV_MATCH_ATS_MODE = 'live'` يشغّل تدفّق المحاكاة.

**الربط الموجود بالفعل:** صفحة المسار تجلب البروفايل وتستخدم اسم ملف الـ CV الحقيقي إن وُجد. هذا الربط للاسم فقط، وليس لتحليل المحتوى.

**المطلوب للربط:** تشغيل تحليل فعلي على سيرة المرشح، ومتابعة حالة التحليل وعرض الدرجة والملاحظات الناتجة عنه.

## 6. محادثات المرشح

**المسار:** `/candidate/chat`، بما في ذلك فتحها من زر الرسائل في الهيدر.

- `createCandidateChatPreview` يُرجع أربع محادثات ثابتة ببيانات مسؤول التوظيف والشركة والصورة وآخر رسالة والتوقيت والرسائل السابقة وعدد غير المقروء.
- حالة المحادثة المغلقة تُحاكى بمعامل `?scenario=closed`.
- البحث يعمل على المصفوفة المحلية، وتحديد المحادثة يصفّر عدّاد غير المقروء محليًا.
- إرسال رسالة أو رد يضيف عنصرًا إلى `useState` فقط؛ لا يصل للطرف الآخر ولا يُحفظ على السيرفر.
- الصور والملفات المختارة تُحوّل إلى روابط `blob:` محلية، ولا تُرفع. مرفق PDF الموجود في المحادثة التجريبية له اسم وحجم فقط، بدون رابط تنزيل.
- منطق الإغلاق وإعادة الفتح في الـ hook المشترك يعدّل الحالة محليًا أيضًا؛ لا يوجد طلب API لهذه العملية.

**المطلوب للربط:** قائمة محادثات ورسائل فعلية، إرسال واستقبال وحفظ الرسائل والردود، رفع وتنزيل المرفقات، تحديث القراءة، وحالات المحادثة. أي بحث أو معاينة محلية يمكن الاحتفاظ بها فوق البيانات الفعلية.

## 7. أسئلة التقديم والتقييم المرتبط بالوظيفة

**المسار:** `/jobs/[slug]` عند تقديم المرشح.

- الإعداد `JOB_APPLY_PREVIEW_ENABLED = true` مفعّل حاليًا.
- إذا لم توجد أسئلة فعلية أو كانت مصفوفتها فارغة، يستخدم التدفق تسعة أسئلة ثابتة من `APPLY_PREVIEW_SCREENING_QUESTIONS`، مثل التوافر الفوري وفترة الإشعار والخبرة والشهادات والراتب.
- إذا كانت قيمة التقييم `null` أو غير موجودة، يستخدم التدفق `APPLY_PREVIEW_ASSESSMENT` بمعرّف `clinical-knowledge` وعنوان `Clinical Knowledge Assessment`.
- لذلك قد تظهر أسئلة أو مطالبة بتقييم حتى عندما لا تحتوي بيانات الوظيفة على أسئلة أو تقييم مرتبط.
- بيانات وقت التقديم المعروضة بعد النجاح تُنشأ بـ `new Date()` في الواجهة. إشعار إرسال رابط التقييم وتاريخ انتهائه يعتمد على الوقت المحلي ومدة 72 ساعة، وليس على بيانات دعوة يعيدها رد التقديم.
- رابط «أداء التقييم» الناتج عن التقييم التجريبي يفتح شاشة التقييم التجريبية الموضّحة في القسم التالي.

**الربط الموجود بالفعل:** التقديم نفسه يرسل `POST` إلى `${getUserApiUrl()}/jobs`، ويتضمن `job_id` وCV عند اختياره، و`screening_answers` عند وجود إجابات. لا يُصنّف إرسال طلب التقديم كعملية محلية؛ لكن تعليق الخدمة يذكر أن عقد إجابات الأسئلة مع الـ backend ما زال معلقًا. وجود الحقل في الطلب وحده لا يثبت حفظه أو معالجته على السيرفر.

**المطلوب للربط:** الاعتماد على أسئلة وتقييم الوظيفة الحقيقيين، اعتماد عقد الإجابات، واستخدام بيانات الدعوة والتوقيت والانتهاء الفعلية عند عرض إشعار التقييم. لا يمكن تأكيد إرسال البريد من الكود الحالي للواجهة وحده.

## 8. أداء التقييم بواسطة المرشح

**المسار:** `/candidate/assessment/[id]`.

- المسار يستدعي `getCandidateAssessmentPreview(id, state)` بدل جلب تقييم المرشح. تغيير `id` يغيّر المعرّف، مع بقاء محتوى التقييم التجريبي نفسه.
- العنوان والجهة المرسلة والبريد والوصف والمدة `45` دقيقة والمحاولات `1` ودرجة النجاح `70` والأسئلة الستة واختياراتها بيانات ثابتة.
- حالة الرابط تأتي من `?state=available|expired|taken|unavailable`، وليست نتيجة تحقق من السيرفر.
- وقت الإرسال يُولّد محليًا؛ وحالة `taken` تستخدم وقت تسليم ومدة تجريبيين ثابتين.
- بدء الاختبار واختيار الإجابات وقفل السؤال والانتقال والتوقيت كلها داخل حالة الصفحة. لا يوجد إنشاء محاولة أو حفظ إجابات على السيرفر.
- التسليم، بما فيه التسليم عند انتهاء الوقت، يسجّل وقتًا ومدة محليين ويفتح رسالة نجاح بدون إرسال الإجابات إلى API.

**المطلوب للربط:** تحميل التقييم المخصص للمرشح والتحقق من صلاحية الدعوة وحالة المحاولة، بدء محاولة وحفظ إجاباتها وتسليمها، وقراءة حالة التسليم الفعلية. شروط المدة وعدد المحاولات وانتهاء الدعوة تحتاج اعتمادًا من السيرفر.

## 9. نسبة مطابقة ثابتة عند غياب نتيجة API

**المواضع:** بطاقات قائمة الوظائف، بطاقات الوظائف المحفوظة، وهيدر تفاصيل الوظيفة، عند عرضها بحساب المرشح.

- المكوّن `JobMatchBadge` يقرأ `score` الممرّر من `job.match_score`، لكنه يستخدم `const matchScore = score ?? 90`.
- إذا رجع الحقل `null` أو لم يرجع، تظهر نسبة `90%` ثابتة للمستخدم رغم عدم وجود نتيجة مطابقة من API.
- عندما توجد قيمة فعلية، يعرض المكوّن قيمة API؛ لذلك المشكلة في البديل الثابت، وليست في كل نسب المطابقة المعروضة.

**المطلوب للربط:** الاعتماد على نتيجة مطابقة فعلية، واعتماد حالة واضحة لعدم توافر النتيجة بدل عرض نسبة تجريبية.

## حدود الحصر والأجزاء المستبعدة

تمت مراجعة بقية صفحات المرشح لتمييز الربط الجزئي عن البيانات التجريبية. الأجزاء التالية لديها طلبات API في التنفيذ الحالي، ولذلك لم تُدرج كميزات ثابتة بالكامل:

- البروفايل الأساسي، النبذة، التعليم، الخبرات، المهارات، ورفع أو حذف CV البروفايل.
- المؤهلات والشهادات والتراخيص المهنية في صفحات `credentials`.
- إعدادات البيانات الأساسية وصورة الحساب وتغيير كلمة المرور.
- قائمة طلبات التقديم والوظائف المحفوظة وإضافة أو إزالة وظيفة محفوظة.
- إشعارات المرشح وعداد الإشعارات في الهيدر.

هذا الاستبعاد يخص وجود الربط في الكود، ولا يضمن اكتمال كل حقل أو نجاح الخدمة أثناء التشغيل. يشمل التقرير الاستثناءات الثابتة داخل الشاشات المتصلة، مثل نسبة `90%` وأسئلة التقديم الاحتياطية ونتيجة ATS؛ ولا يشمل عناصر عرض ناقصة الربط لا تستخدم بيانات تجريبية أصلًا.
