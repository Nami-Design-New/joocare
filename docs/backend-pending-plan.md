# المطلوب من الباك: فلو الوظائف والتقييمات

آخر تحديث: 22 نوفمبر 2026. كل بند هنا اتأكد بطلبات حية على سيرفر التست. التفاصيل الكاملة والأدلة في [job-post-apply-assessment-api-audit.md](job-post-apply-assessment-api-audit.md).

`C` = `{{companyUrl}}`، `U` = `{{userUrl}}`.

## 1. نشر الوظيفة وأسئلة التقديم

| # | المطلوب | الوضع الحالي | الفرونت دلوقتي |
| - | ------- | ------------ | -------------- |
| 1.1 | إرجاع `template_id` لكل سؤال في `GET C/jobs/{id}` | بيرجع `is_general: true` بس، من غير ما يحدد القالب | بيستخدم `is_used` من `question-templates-hints?job_id=` |
| 1.2 | حفظ `question_templates[i][is_required]` | بيتجاهله، والقالب بيرجع `is_required: true` دايمًا | بيبعته عادي |
| 1.3 | دعم `mark` (درجة سؤال التقديم) في الحفظ والقراءة | مش موجود | بيبعته ومستني الدعم |

## 2. تقديم المرشح ودعوة التقييم

| # | المطلوب | الوضع الحالي | الفرونت دلوقتي |
| - | ------- | ------------ | -------------- |
| 2.1 | `GET U/jobs/{id}`: إرجاع `assessment_id` (أو object مختصر للتقييم) | مش راجع | مودال النجاح مش بيعرف إن الوظيفة فيها تقييم |
| 2.2 | `POST U/jobs`: إرجاع بيانات الدعوة (ID التقييم و`expires_at`) | بيرجّع `application` بس، مع إن الدعوة بتتعمل فعلًا | مودال النجاح عام، من غير رابط للتقييم |
| 2.3 | `GET U/applications`: إرجاع حالة التقييم ورابطه لكل تقديم | مش راجع، والترتيب الأقدم أولًا | حالة التقييم في صفحة التقديمات متعلّقة بكومنت |

## 3. أداء المرشح للتقييم

| # | المطلوب | الوضع الحالي | الفرونت دلوقتي |
| - | ------- | ------------ | -------------- |
| 3.1 | endpoint لقائمة تقييمات المرشح | `GET U/assessments` بيرجّع 404 | الفلو شغال بالرابط المباشر بس |
| 3.2 | بيانات العداد: `attempt_expires_at` بصيغة ISO مع timezone و`server_time`، أو `remaining_seconds`، في التفاصيل وstart وanswer | `started_at` نص نسبي، ومفيش وقت متبقي | بيعرض مدة التقييم من غير عد تنازلي |
| 3.3 | توضيح التسليم لما الوقت يخلص أو لو المرشح عايز يسلّم بدري: تلقائي من السيرفر ولا محتاج endpoint، وشكل الرد | مش موثّق | بيحذّر المرشح لو خرج قبل ما يخلّص |
| 3.4 | `POST U/assessments/{id}/answer`: رفض إعادة إجابة سؤال اتحفظ قبل كده | بيقبله وبيستبدل الإجابة القديمة | الواجهة مش بتبعت كده |

## 4. الشركة: المتقدمين على الوظيفة

| # | المطلوب | الوضع الحالي | الفرونت دلوقتي |
| - | ------- | ------------ | -------------- |
| 4.1 | `GET C/applications/{jobId}`: إرجاع إجابات أسئلة التقديم لكل متقدم | الرد فيه `id, user, job_id, cv` بس | نافذة الإجابات على بيانات تجريبية |
| 4.2 | نفس الـ endpoint: حالة التقييم و`result_id` لكل متقدم | مش راجع | عمود التقييم بيعرض «Not assigned» |
| 4.3 | نفس الـ endpoint: `created_at` بتاريخ قابل للتحويل (ISO) | نص نسبي («just now») | بيعرض «Invalid Date» (محتاج إصلاح فرونت كمان) |

## 5. نتائج التقييم

| # | المطلوب | الوضع الحالي | الفرونت دلوقتي |

## 6. تفاصيل التقييم ومكتبة التقييمات

| # | المطلوب | الوضع الحالي | الفرونت دلوقتي |
| - | ------- | ------------ | -------------- |
| 6.1 | endpoint لإيقاف التقييم وendpoint لاستئنافه، ومعاهم `paused_at` وعدد المرشحين اللي خلّصوه في `GET C/assessments/{id}` | مش موجود | زرار «Pause #» بيعرض «قريبًا» |
| 6.2 | `GET C/assessments/{id}`: مين عمل التقييم `{ id, name, role_label }` زي `admin` في الملاحظات | مش راجع | كارت «Created By #» بيعرض «—» |
| 6.3 | عدد التقييمات في كل تصنيف، وعدد الوظائف المرتبطة والدعوات الخارجية لكل تقييم | مش راجعين | أرقام ثابتة بجنبها `#` |
| 6.4 | توحيد ترتيب الأسئلة بين `GET C/questions` و`GET C/assessments/{id}` | الأولى الأحدث أولًا، والتانية الأقدم أولًا | — |
| 6.5 | تصحيح `has_file` في رد السؤال | بيرجع `false` مع وجود ملف | بيعتمد على `files` |

## لما الباك يخلّص

- بند 2: نوصّل مودال النجاح بالدعوة الحقيقية، ونفعّل حالة التقييم في صفحة التقديمات.
- بند 3: نضيف العداد، والتسليم لما الوقت يخلص، وقائمة تقييمات المرشح.
- بند 4: نوصّل نافذة إجابات التقديم وعمود التقييم عند الشركة.
- بند 6: نشيل علامات `#` ونوصّل الإيقاف والاستئناف وكارت «Created By».
- بند 7: نوصّل اسم المرشح في النتائج بصفحة البروفايل، والصفحة نفسها بالـ endpoint الجديد.
